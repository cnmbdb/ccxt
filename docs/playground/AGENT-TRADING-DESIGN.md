# AI 量化交易 Agent 接入设计

## 当前状态

控制台可编辑策略；现有 Agent 和策略接口将配置写入 D1。当前没有可验证的定时执行、模型决策、订单执行、对账和风控闭环。`trade_audit` 表存在，但不能因此认定已实现审计。现有服务端接口未见身份认证，不能直接接入交易凭证或实盘执行。

## 接入边界

- Binance Agent OS 是工具集合。MCP、交易 API 和 Skills Hub 需要分别接入；Skills Hub 中的说明文件不是可以自动执行的服务。
- Binance MCP 用于用户授权的行情和账户查询；币安官方文档要求交易、撤单和转账在执行前由用户确认，不能假设该接口支持无人确认的自动下单。
- 无人值守的实盘执行使用独立的 Binance 交易 API 适配器，必须基于用户配置的账户、交易权限和独立风控，而不是绕过 MCP 的确认流程。
- AI 模型接入使用服务端适配器；模型尚未配置时不得生成订单。Binance AI Pro 是币安应用内产品，不能假设它提供可供此项目调用的模型 API。

## 运行流程

1. 调度器为启用的策略创建具有唯一标识的运行记录，防止同一周期重复执行。
2. 获取行情及账户快照，检查数据时间、市场状态和交易对过滤器；信息不足时停止运行。
3. 模型输出经严格 schema 验证的建议（买入、卖出或观望），模型不能直接调用下单工具。
4. 独立风控根据允许的交易对、资金和仓位限制、价格偏差、订单频率、日亏损、熔断状态及交易所规则决定是否允许执行。缺失配置、异常或过期数据默认拒绝。
5. 执行器先持久化订单意图和唯一 client order ID，再发送订单；超时或状态不明时先按 client order ID 查询并对账，禁止盲目重试。
6. 持续更新订单、成交、余额和运行审计；异常时停止新单并通知用户。紧急停止应阻止新单，并明确是否撤销已有订单。

## 启用实盘前必须完成

- 给所有管理和执行接口增加服务端身份认证、授权和租户隔离；确认公开入口不能匿名修改策略或触发交易。
- 独立管理服务端交易密钥，禁止输出到日志、浏览器或代码仓库；限制交易权限和 IP，不启用提现权限。
- 确认交易类型、交易对、单笔及总持仓上限、单日亏损和停机规则；不得用 UI 示例数值作为实盘授权。
- 配置持久化调度、并发锁、状态机、订单对账、熔断、审计与告警；重启、重试、部分成交和异常均需覆盖。
- 先在对应的 Binance 测试网或模拟环境完成端到端验证，再由用户配置真实账户和模型。实盘测试遵守仓库的单笔低于 25 美元规则，永不测试提现。
